## Detailed Findings

### Critical

#### C1. Nil-pointer dereference in Tree.Format
- **File**: `internal/pkg/tree/tree.go:41-46`
- **Problem**: When `t.root == nil`, the method writes "∅" but has no `return` statement, so execution falls through to `t.root.Format(f, verb)` which panics with a nil-pointer dereference. Any `fmt.Sprintf("%v", emptyTree)` will crash. The sibling method `String()` (line 34-38) correctly uses `if/return/else`.
- **Fix**: Add `return` after `fu.WriteString(f, "∅")`.

#### C2. fanout16.go sets FanoutBits = 2 (should be 4)
- **File**: `internal/pkg/depth/fanout16.go:6`
- **Problem**: The `branch16` build tag sets `FanoutBits = 2` (fanout 4), identical to the default. Should be `FanoutBits = 4` (since `1 << 4 = 16`). Building with `-tags branch16` silently produces a fanout-4 tree. Impact mitigated because this tag is never used in CI or default builds, but anyone using it gets wrong behavior.
- **Fix**: Change `FanoutBits = 2` to `FanoutBits = 4`.

### High

#### H1. Data race on packer.mask in parallel Combine
- **File**: `internal/pkg/tree/branch.go:118-130`
- **Problem**: In `branch.Combine`, the parallel callback calls `ret.p.SetNonNilChild(i, y)` which does `p.mask |= masker.NewMasker(i)` -- a concurrent read-modify-write on the shared `mask` field from multiple goroutines. The `updateMask()` at line 131 recomputes the correct value, but the intermediate `|=` operations are a data race under the Go memory model. The same pattern appears in `Intersection` (line 232). `Difference`, `Map`, and `Where` correctly use direct `ret.p.data[i] =` assignment instead.
- **Fix**: Replace `ret.p.SetNonNilChild(i, y)` / `ret.p.SetNonNilChild(i, x)` with direct `ret.p.data[i] = y` / `ret.p.data[i] = x` in the parallel callback, matching the `Difference` pattern. `updateMask()` already handles it.

#### T-1. CI races job has undefined matrix variable
- **File**: `.github/workflows/go.yml:48-51`
- **Problem**: The `races` job references `${{ matrix.go }}` in `setup-go` but has no `strategy.matrix` defined. The Go version is empty/undefined, so `setup-go@v1` uses an arbitrary default. CI still runs but tests against the wrong Go version. Also uses outdated `actions/setup-go@v1` and `actions/checkout@v1`.
- **Fix**: Either add a `strategy.matrix` with desired Go versions, or hard-code a version. Update action versions to v4/v3+.

#### T-2. CI races job only tests root package
- **File**: `.github/workflows/go.yml:58`
- **Problem**: Runs `go test -race -short` without `./...`, so only tests the root package. Misses all internal packages where actual concurrency lives (depth, tree). Combined with H1, the real data race is never caught by CI.
- **Fix**: Change to `go test -race -short ./...`.

### Medium

#### M-H3. leaf.Add/AddFast mutate in place
- **File**: `internal/pkg/tree/leaf.go:105-131`
- **Problem**: `Add` and `AddFast` mutate `l.data` in place (both modification and append). These are only used from `Builder` (the mutable construction path), but the `node` interface doesn't distinguish mutable vs immutable operations. If `Add` were ever called on a shared leaf, it would corrupt the immutable tree. The paired `With`/`WithFast` methods correctly create copies.
- **Fix**: Add comments documenting that `Add`/`AddFast` are builder-only and must not be called on shared nodes.

#### M1. Set.Difference hardcodes NonParallel gauge
- **File**: `set.go:263`
- **Problem**: `Union` and `Intersection` compute a gauge from set size for parallel execution, but `Difference` always uses `depth.NonParallel`. For large sets this is asymmetrically slow. The internal `branch.Difference` already accepts a gauge parameter.
- **Fix**: Use `s.gauge()` or equivalent, matching Union/Intersection.

#### M2. Masker.String() panics unconditionally
- **File**: `internal/pkg/masker/masker.go:35-38`
- **Problem**: Always panics with `ErrUnimplemented`. If any debug/logging code calls `fmt.Stringer` on a `Masker`, the program crashes. Internal type, so low exposure, but still a trap.
- **Fix**: Implement a basic binary representation, or remove the method.

#### S9. golang.org/x/sys outdated
- **File**: `go.mod:7`
- **Problem**: `golang.org/x/sys v0.13.0` is 28 minor versions behind latest (v0.41.0). Indirect dependency from `arr-ai/hash`. No known CVEs affecting this library (no syscall usage), but consumers of `frozen` who also import `x/sys` may be held back.
- **Fix**: `go get golang.org/x/sys@latest && go mod tidy`.

#### T-6. Infinite loop on test failure
- **File**: `set_test.go:449-452`
- **Problem**: If the assertion at line 444 fails, the test enters an infinite `for { ... }` loop that repeatedly calls `frozen.SetMap`, presumably for attaching a debugger. Without a debugger, the test hangs forever.
- **Fix**: Remove the loop or gate it behind an env var.

#### B-2. make vet not in CI or docs
- **File**: `Makefile:19-22`
- **Problem**: The `make vet` target runs tests with `-tags frozen_vet` for structural tree verification. This is valuable but not wired into `make all`, `make ci`, or the CI pipeline, and is not documented in CLAUDE.md.
- **Fix**: Document in CLAUDE.md. Consider adding to CI (at least on one Go version).

#### T-3. No tests for depth/value/iterator/fu
- **File**: Multiple internal packages
- **Problem**: `depth/gauge.go` (goroutine-spawning parallelism dispatcher), `value/value.go` (`unsafe.Pointer` casts for equality), `iterator/` (bit and slice iterators), and `fu/` have zero test files. The depth package is critical concurrent code. These are covered indirectly through integration tests, but the H1 race shows gaps can hide.
- **Fix**: Prioritize unit tests for `depth.Gauge.Parallel` and `value.Equal`/`value.EqualFuncFor`.

#### D-1. README is sparse and outdated
- **File**: `README.md`
- **Problem**: Minimal: badge, one-line description, two bullet points, pre-generics benchmarks. Doesn't mention generics, `IntSet`, `Key[T]`, builders, `lazy/`, `pkg/rel/`, or have usage examples.
- **Fix**: Update with current type signatures, basic examples, package overview.
