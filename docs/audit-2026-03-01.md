## Detailed Findings

### #1 [High] differenceSet.Has uses union logic

**File**: `lazy/set_diff.go:20-22`

```go
func (s *differenceSet) Has(el any) bool {
    return s.a.Has(el) || s.b.Has(el)  // BUG: should be s.a.Has(el) && !s.b.Has(el)
}
```

Returns true if the element is in *either* set — that's union, not difference.
Any caller using `lazy.Difference(a, b).Has(x)` gets wrong results when `x` is
in `b` but not in `a`.

**Fix**: `return s.a.Has(el) && !s.b.Has(el)`

### #2 [High] unionSet.FastHas never consults s.b

**File**: `lazy/set_union.go:34-38`

```go
func (s *unionSet) FastHas(el any) (has, ok bool) {
    if has, ok = s.a.FastHas(el); ok {
        return has, ok       // BUG: returns (false,true) without checking b
    }
    return s.a.FastHas(el)   // BUG: should be s.b.FastHas(el)
}
```

Two bugs: (1) early return when `s.a` reports `(false, true)` — should still
check `s.b`; (2) fallback queries `s.a` again instead of `s.b`. Elements only
in `b` are never found via `FastHas`.

**Fix**:
```go
func (s *unionSet) FastHas(el any) (has, ok bool) {
    if has, ok = s.a.FastHas(el); ok && has {
        return true, true
    }
    return s.b.FastHas(el)
}
```

### #3 [High] differenceSet.FastHas queries s.a twice and lacks difference semantics

**File**: `lazy/set_diff.go:24-28`

```go
func (s *differenceSet) FastHas(el any) (has, ok bool) {
    if has, ok = s.a.FastHas(el); ok {
        return        // BUG: returns a's answer without checking b
    }
    return s.a.FastHas(el)  // BUG: should be s.b, and needs AND-NOT logic
}
```

Even fixing the `s.a → s.b` typo isn't enough — difference requires
`has_in_a && !has_in_b`.

**Fix**:
```go
func (s *differenceSet) FastHas(el any) (has, ok bool) {
    aHas, aOk := s.a.FastHas(el)
    if aOk && !aHas {
        return false, true
    }
    bHas, bOk := s.b.FastHas(el)
    if bOk && bHas {
        return false, true
    }
    return aHas && !bHas, aOk && bOk
}
```

### #4 [High] symmetricDifference inherits Has bug (NEW)

**File**: `lazy/set_symmdiff.go:3-5`

```go
func symmetricDifference(a, b Set) Set {
    return a.Difference(b).Union(b.Difference(a))
}
```

This composes two `differenceSet`s inside a `unionSet`. The outer `unionSet.Has`
calls `differenceSet.Has` on each side, which uses `||` instead of `&& !`.
Result: `Has` returns wrong answers on symmetric difference sets.

**Fix**: Fixing #1 fixes this transitively.

### #5 [High] EmptySet.Equal compares argument to itself (NEW)

**File**: `lazy/set_empty.go:39-43`

```go
func (EmptySet) Equal(set any) bool {
    if set, ok := set.(Set); ok {
        return set.EqualSet(set)  // BUG: shadows outer 'set'; compares arg to itself
    }
    return false
}
```

The inner `set` shadows the parameter. `set.EqualSet(set)` compares the argument
to itself, always returning `true`. `EmptySet{}.Equal(nonEmptySet)` incorrectly
returns `true`.

**Fix**: `return set.IsEmpty()` (matching the pattern in `EqualSet` at line 46-48).

### #6 [High] Lazy Has/FastHas/Equal bugs undetected by tests (NEW)

**File**: `lazy/set_test.go`, `lazy/testutil_test.go`

All lazy set tests compare results via `assertEqualSet`, which calls
`EqualSet`, which calls `Freeze()`, which materializes via `Range()`. The
`Range()` iterators are correct — they properly filter elements. So tests pass
despite `Has`/`FastHas`/`Equal` being broken.

`assertSetOps` (testutil_test.go:101) does test `Has` at line 131, but only on
`frozenSet` inputs (from `set_frozen_test.go`), never on composite lazy sets
(difference, union, symmetricDifference).

`TestSet` (set_test.go:34) is the only test that creates composite lazy sets,
but it only uses `assertEqualSet`, not `assertSetOps`.

**Fix**: Add targeted tests for `Has`, `FastHas`, and `Equal` on all composite
lazy set types (difference, union, intersection, symmetricDifference, where,
map) with known elements. Include `EmptySet.Equal(nonEmpty)` case.

### #7 [High] baseSet.Hash is non-deterministic for lazy sets (NEW)

**File**: `lazy/set_base.go:76-82`

```go
func (s *baseSet) Hash(seed uintptr) uintptr {
    h := hash.Uintptr(hashSeed, seed)
    for i := s.set.Range(); i.Next(); {
        h = hash.Any(i.Value(), h)  // BUG: order-dependent chaining
    }
    return h
}
```

Hash uses chained accumulation (`h = hash.Any(val, h)`) which is
order-dependent. Since lazy set iteration order can vary between different
expressions yielding the same logical set, two equal lazy sets can produce
different hash values. This violates `Equal(a, b) => Hash(a) == Hash(b)`.

Compare with `frozen.Set.Hash` which correctly uses XOR: `h ^= hash.Any(val, seed)`.

**Fix**: `h ^= hash.Any(i.Value(), seed)` (XOR accumulation, matching frozen.Set).
