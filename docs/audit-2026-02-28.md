## Detailed Findings

### #1 [High] differenceSet.Has uses union logic

**File**: `lazy/set_diff.go:21`

```go
func (s *differenceSet) Has(el any) bool {
    return s.a.Has(el) || s.b.Has(el)  // BUG: should be s.a.Has(el) && !s.b.Has(el)
}
```

`Has` returns true if the element is in *either* set — that's union, not difference. Any caller using `lazy.Difference(a, b).Has(x)` gets wrong results.

**Fix**: `return s.a.Has(el) && !s.b.Has(el)`

### #2 [High] unionSet.FastHas never consults s.b

**File**: `lazy/set_union.go:35-38`

```go
func (s *unionSet) FastHas(el any) (has, ok bool) {
    if has, ok = s.a.FastHas(el); ok {
        return has, ok
    }
    return s.a.FastHas(el)  // BUG: should be s.b.FastHas(el)
}
```

Copy-paste error: the fallback queries `s.a` again instead of `s.b`. Elements only in `b` are never found via `FastHas`.

**Fix**: Change second call to `return s.b.FastHas(el)`

### #3 [Medium] differenceSet.FastHas never consults s.b

**File**: `lazy/set_diff.go:24-28`

Same copy-paste pattern as #2 — second call should be `s.b.FastHas(el)`.

### #7 [Low] IntSet undefined behaviour with negative integers

**File**: `intset.go:25-27`

`locateCell` does `i % cellBits` which returns a negative value for negative `i` in Go. `cellMask(1) << uint(negative)` wraps to a huge shift, producing wrong results silently.

**Fix**: Document that `IntSet` is for non-negative integers, or add a guard.
